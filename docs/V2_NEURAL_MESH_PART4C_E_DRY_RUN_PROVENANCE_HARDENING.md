# V2 Neural Mesh Part 4C-E: Dry Run Provenance Hardening

## Purpose

Dry Run Provenance Hardening separates dry-run generated mesh intelligence from real runtime truth. Brain Outputs and Coordinator Decisions created by the first intelligence dry run remain valuable for observability, but they must never be presented as production runtime decisions or Paper-ready evidence.

This phase is non-executing. It does not create orders, order intents, Paper positions, Shadow orders, Live orders, AI calls, or strategy/risk/exit behavior.

## Provenance Contract

The latest provenance analysis lives in `dry_run_provenance_analysis`, keyed by `object_type` and `object_id`.

Supported object types:
- `SIGNAL`
- `BRAIN_OUTPUT`
- `COORDINATOR_DECISION`
- `QUALITY_EVALUATION`
- `PROCESSING_STATE`
- `LINK_COVERAGE`
- `LINEAGE_COVERAGE`

Core fields:
- `generated_by`
- `dry_run_id`
- `producer_name`
- dry-run/runtime/adapter/manual booleans
- `provenance_status`
- `provenance_confidence`
- `provenance_reason`
- `can_feed_brain_by_provenance`
- `can_feed_paper_by_provenance`
- source table and creation timestamp

Run summaries live in `dry_run_provenance_runs`.

## Generated By

Allowed values:
- `dry_run`
- `runtime`
- `adapter`
- `manual`
- `unknown`

`mesh_dry_run` is normalized to `dry_run`.

## Provenance Status

Allowed values:
- `RUNTIME_VERIFIED`
- `DRY_RUN_ONLY`
- `ADAPTER_GENERATED`
- `MANUAL_GENERATED`
- `UNKNOWN`
- `MIXED`
- `ERROR`

Unknown provenance blocks Paper evidence.

## Classification Rules

- Explicit `generated_by=dry_run` or `generated_by=mesh_dry_run` becomes `DRY_RUN_ONLY`.
- Explicit `dry_run_id` becomes `DRY_RUN_ONLY`.
- Coordinator Decisions inherit dry-run status when all input Brain Outputs are dry-run generated.
- Explicit runtime provenance becomes `RUNTIME_VERIFIED`.
- Explicit adapter provenance becomes `ADAPTER_GENERATED`.
- Explicit manual provenance becomes `MANUAL_GENERATED`.
- Conflicting dry-run/runtime metadata becomes `MIXED`.
- Missing metadata becomes `UNKNOWN`.

No provenance is fabricated. Missing provenance remains missing.

## Confidence Rules

- Explicit generated_by: `0.95`
- Explicit dry_run_id: `0.95`
- Producer with generated_by: up to `+0.03`
- Inferred dry-run from local metadata or linked inputs: `0.80`
- Unknown: `0.20`
- Mixed/conflicting metadata: `0.40`

Scores are clamped from `0.0` to `1.0`.

## Dashboard Truth

The dashboard endpoint is:

- `GET /dashboard/api/v2/dry-run-provenance`

It reports:
- Brain Outputs total/runtime/dry-run
- Coordinator Decisions total/runtime/dry-run
- Signals runtime/dry-run
- generated_by counts
- provenance status counts
- dry-run grouping by id
- producer coverage
- unknown provenance count
- blocked-from-Paper count
- can-feed-Paper provenance count
- `paper_ready=false`

The Mesh Dashboard includes `layers.dry_run_provenance` and `flow.dry_run_provenance`.

## API Routes

- `GET /provenance/dry-run/recent`
- `GET /provenance/dry-run/{object_type}/{object_id}`
- `POST /provenance/dry-run/analyze/recent`
- `GET /dashboard/api/v2/dry-run-provenance`

All routes return `mock_data=false`.

## Readiness Blockers

Mesh readiness adds:
- `BRAIN_OUTPUTS_DRY_RUN_ONLY`
- `COORDINATOR_DECISIONS_DRY_RUN_ONLY`
- `DRY_RUN_EVIDENCE_BLOCKED_FROM_PAPER`
- `PROVENANCE_UNKNOWN`
- `DRY_RUN_PROVENANCE_ANALYSIS_MISSING`

## Safety Rules

- Dry-run evidence can feed observability only.
- Dry-run evidence cannot feed production Paper readiness.
- Unknown provenance cannot feed Paper readiness.
- `paper_ready` remains false.
- No execution path is touched.
- No order or order intent is created.
- No private key or signing path is used.
