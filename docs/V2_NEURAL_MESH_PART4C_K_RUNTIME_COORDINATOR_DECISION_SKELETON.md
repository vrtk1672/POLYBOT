# V2 Neural Mesh Part 4C-K: Runtime Coordinator Decision Skeleton

## 1. Purpose
Part 4C-K adds the first non-executing runtime Coordinator producer. It reads runtime Brain Outputs and writes runtime Coordinator Decisions without creating strategy routes, risk approvals, exit plans, order intents, orders, fills, positions, or live actions.

## 2. Why This Matters
Before this phase, POLYBOT had runtime Brain Outputs but all Coordinator Decisions were dry-run generated. This phase proves the mesh can now reconcile runtime Brain truth into runtime Coordinator truth while keeping `NO_TRADE` and blocked states first-class.

## 3. Scope
Implemented:
- Runtime Coordinator contract.
- Runtime Brain Output candidate selection.
- Deterministic Coordinator classification.
- Runtime Coordinator run persistence.
- Runtime Coordinator input persistence.
- Runtime Coordinator API and dashboard endpoint.
- Mesh dashboard runtime Coordinator layer.
- Dry-run/runtime provenance refresh after decision creation.
- Producer health and mesh blocker refresh hooks.

Explicitly not implemented:
- Paper trading.
- Live trading.
- Order intents.
- Orders.
- Fills.
- Positions.
- Strategy routing.

- Exit plans.
- Opportunity scoring.
- AI calls.

## 4. Runtime Coordinator Contract
The adapter only reads Brain Outputs that are:
- generated by runtime
- generated by `runtime_brain_adapter`
- not dry-run generated
- explicitly non-executing
- explicitly not Paper allowed

Each runtime Coordinator Decision is marked in metadata:
- `generated_by=runtime`
- `producer_name=runtime_coordinator_adapter`
- `generated_from=runtime_brain_output`
- `is_runtime_generated=true`
- `is_dry_run_generated=false`
- `source_brain_output_ids=[...]`
- `source_signal_ids=[...]`
- `paper_allowed=false`
- `execution_allowed=false`
- `order_intent_allowed=false`

The core `coordinator_decisions.execution_allowed` column remains protected by its existing `CHECK (execution_allowed = false)` constraint.

## 5. Coordinator Decision Logic
The adapter uses deterministic non-AI logic:
- Runtime `WEAK_SIGNAL` Brain Outputs become `NO_TRADE`.
- Runtime `NO_TRADE_CANDIDATE` Brain Outputs become `NO_TRADE`.
- Missing market link blocks Paper eligibility.
- Missing Orderbook, Risk Core, and Exit Foundation are always preserved as blockers.
- Higher-quality observe-style Brain Outputs would become hold-for-more-evidence rather than executable decisions.

All decisions are interpretive only.
